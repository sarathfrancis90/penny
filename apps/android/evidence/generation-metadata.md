# Metadata-only generation verification

`VaultGenerations.readVerified` returns immutable vault/snapshot identity, timestamp, counts, expense total, receipt-byte total and authenticated membership digest. It returns no record catalog, receipt handles, image bytes or base64. Verification still temporarily materializes bounded expense, finance and descriptor collections; this is not constant-memory verification or a new capacity claim.

An explicit private `SnapshotHydration` adapter retains the existing public snapshot behavior and final `Snapshot.validate`. Both paths share strict row decryption/decoders and cross-domain validation. The metadata path reuses `Snapshot.validate` with no attachments for identity/expense/finance semantics, checks global receipt count/uniqueness/owners/bytes, verifies the unchanged membership digest, then requires complete authenticated receipt reopen, native image decode, both inventories and successful close before returning. Borrowed receipt bytes retain the existing `finally` wipe.

Preparation, pending activation recovery, recorded predecessor validation, post-write validation, prepublication verification and `vaultId` now use this path without hydration. Snapshot/checkpoint and mutation input callers explicitly hydrate. Schema, header/digest format, portable v1–v3 formats, existing caps, state/key binding, publication cancellation and recovery rules are unchanged. This is an internal seam, not a candidate admission or v4 integration.

Build, assembly, 25 JVM tests and lint passed. **23/23** focused device tests passed independently on API 26 / 4 KiB and API 37 / 16 KiB arm64 emulators. Exact source/APK/log/report hashes, commands and fingerprints are in [generation-metadata.json](generation-metadata.json). Raw evidence and frozen APKs are retained locally under `artifacts/offline/metadata-generation/`.

Four new `GenerationMetadataDeviceTest` groups prove summary parity with all-domain snapshots; immutable counts; preparation/recovery/metadata/vault-ID verification without requesting the snapshot adapter; matching rejection of authenticated missing receipt/financial owners and duplicate budget pairs; header/membership/key failures preserving evidence; and rejection of a receipt with valid AEAD, matching hash, matching membership and accepted structural PNG metadata whose native image decoder fails. Existing generation (5), receipt (8), mutation (4) and local restore cancellation/tamper (2) groups cover the changed validation callers. No new process-death, full UI, cloud-provider, benchmark or Swift-parity run is claimed.

Tests used only `ca.penny.offline.dev.test` with unique owned directories/databases/aliases. Both sandbox processes were stopped, the owned API 26 emulator was shut down, and the normal development demo was unchanged. Earlier hydration/durable evidence remains a record of its original source, not this revision.
