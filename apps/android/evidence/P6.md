## Storage corrections

Initial native measurements exposed repeated per-row Keystore IPC: 10k expense reopen 13.139 s, edit 13.032 s plus snapshot refresh 12.920 s. Portable decode took 31.529 s because repeated ICU numeric regex matching scaled poorly on the complete document.

`VaultStore` now encrypts rows with a random AES-256 data key wrapped by the existing Android Keystore key. Wrapped key metadata, its format/generation, and every legacy row migrate in one SQLite transaction. All expense/receipt/finance plaintext authenticates and validates before commit. Receipt migration reads ciphertext in bounded chunks. Confirmed full restore installs a fresh key generation inside its existing transaction. Every operation authenticates and unwraps the persisted envelope inside its transaction, then uses that software key for its row batch. Android8 Keystore equality compares alias/UID rather than key material, so the intermediate cache shortcut was removed. Key loss, corruption, missing metadata and a changed generation cannot bypass revalidation. Receipt deletion also validates the current key before mutating storage. No portable format changes were made.

Android8 runtime testing additionally exposed `SQLiteOpenHelper` lacking the later AutoCloseable interface. `VaultStore` now explicitly implements Closeable, including the worker's use block. On this Android8 image, a single Keystore call with a 2,796,436-byte plaintext lost 41 × 65,536 bytes of output. Explicit 16KiB update calls preserve complete legacy ciphertext/decrypted output, and migration requires the exact GCM plaintext length before parsing. No authentication fallback exists; already truncated legacy ciphertext requires a verified portable backup. Diagnostic logs preserve the direct, imported-key and bounded-call observations.

The Android8 bitmap decoder accepted an invalid PNG zlib stream as partial pixels. The intake gate now checks every chunk/CRC, contiguous IDAT, complete zlib stream and checksum, exact noninterlaced/Adam7 scanline byte counts, and filter bytes 0–4. It uses a bounded 8KiB output buffer and runs before conversion as well as before save/restore. Both native implementations consume the public shared `png-integrity-corpus.json`; valid originals remain byte-identical.

`StrictJson` scans RFC8259 number tokens linearly using ASCII digits, with the same required fraction/exponent and structural delimiter rules. Tests reject leading plus/zeros, missing fraction/exponent digits, NaN/Infinity, Unicode digits and extra tokens, and parse a 10k mixed document.

`RowKeyMigrationDeviceTest` covers authenticated legacy migration across all domains, a late savings-row write failure preserving exact original ciphertext/metadata, current key generation across two connections, failed restore rollback to the old generation, missing/corrupt wrapped keys, finance-only Keystore loss and explicit verified recovery, same-alias wrapping-key replacement, stale receipt deletion after DEK/KEK loss or corruption, and a 2 MiB legacy receipt larger than CursorWindow. The ordinary P2/P3/P4/P5/P5b tests remain required.
