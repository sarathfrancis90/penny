## Recovery and file export

The key-display and restore dialogs enforce secure windows; key re-entry uses password input and is never saved in activity state. Re-entry must match before the portable key is encrypted under a separate Android Keystore alias and atomically stored in `noBackupFilesDir`. Missing protected-key reads fail closed; an explicitly re-entered separately saved key can recreate the confirmation copy. Sensitive copy marks the clipboard and clears only owned matching content on dismissal or after a minute; old Android clipboard access is not eliminated by that marker.

Device tests verify mismatch refusal without overwriting the confirmed key, device-key loss, explicit re-confirmation, sealed storage without plaintext key bytes, native resolver export, injected write/readback/truncation failures and staging cleanup. The UI mismatch flow checks the sensitive clipboard marker, preserves the confirmed key and cancels an actual DocumentsUI picker without exporting. The picker can first consume Back to dismiss its filename keyboard; the test verifies return to the app and absence of the key dialog.

Every filename includes a fresh UUID. Export encrypts first, stages only ciphertext in private no-backup storage, flushes/syncs/reopens and authenticates it, then opens the destination without truncation. A nonempty or unknown-size destination is refused. A collision test proves prior encrypted bytes remain intact. Successful new writes are flushed/synced, read back, compared byte-for-byte and authenticated before reporting file export success. Injected failures never report success; an incomplete newly chosen destination may remain for the user to remove. No successful export implies a remote cloud upload or retention guarantee.
