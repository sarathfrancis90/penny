# P5 Android private Drive transport — local evidence

Date: 2026-09-13. Development sandbox `ca.penny.offline.dev.test`, API 36 Android 16 arm64 emulator `emulator-5556`. This records a bounded manual backup slice, not real OAuth consent, actual account upload, automatic scheduling, cloud-sync or release readiness.

## Implemented

- Exact cloud-v1 manifest/envelope/tag/name/descriptor validation and AES-256-GCM AAD separation. Shared public golden manifest decrypts and deterministic nonce test reproduces nonce/ciphertext/tag. Original snapshot v1/v2/v3 wire version is verified before in-memory schema upgrade. Native receipt image decoding follows snapshot authentication.
- Deterministic four-phase publication reducer and guarded transport orchestration. Account, vault incarnation, recovery state, session epoch and ten-minute operation lifetime are checked around every provider await. Wrong/late operation events cannot advance publication. Both remote objects are downloaded and checked for exact bytes, SHA-256 and authenticated semantics before last-good advances.
- Google Identity AuthorizationClient 21.6.0, explicit account picker and `drive.appdata` scope. Stable account tag derives from opaque `about.user.permissionId`. Only the fixed HTTPS Drive origin is called by the app-owned adapter; redirects and custom global cookie handlers are refused. Resumable **create** first POSTs metadata and then PUTs bytes to an exact-host/path validated upload-session URI; it does not update a file resource. A 6 MiB fake-connection test checks this large-backup path. No Google account was configured or authorized during development tests.
- Encrypted no-backup local settings under their own Android Keystore alias, durable per-attempt publication revision, key tag and vault incarnation, and separate last-good data revision. Retry/unchanged data never reuse the same writer/revision. Post-write verification failure restores/verifies exact prior ciphertext; an interrupted unverified write fails closed. Lost settings key does not create a replacement over existing data.
- Complete bounded inventory and discovery, duplicate ID/name/token rejection, independent vault/writer/revision chooser and no automatic deletion. Before publication reservation, inventory must have at most 99 manifests and 998 total objects. Unknown objects and old-key manifests count. Individual unauthenticated/invalid manifests are excluded with a visible count; provider or listing failures abort discovery. Mixed old/new keys remain discoverable. Capacity can still race across independent concurrent writers.
- Cloud restore retains a suspend commit action after preview: it checks account identity again and the recovery/session/vault guards immediately before local atomic replacement, which also rejects any intervening data revision. Cancelling, disabling, changing account/key or restoring a vault invalidates the old operation/binding. A portable-file restore stays independent of provider access.
- Native default-disabled configuration UI, key re-entry, manual enable/backup/discovery/cancel/disable, progress and separate file-export/Drive verification wording. Core expense/receipt/finance/file-backup controls remain available without Drive configuration.

## Configuration and network boundary

Both `pennyDriveAndroidClientId` and `pennyDriveSigningSha256` default empty. BuildConfig fields `DRIVE_ANDROID_CLIENT_ID` / `DRIVE_SIGNING_SHA256` and manifest metadata `ca.penny.offline.DRIVE_ANDROID_CLIENT_ID` / `ca.penny.offline.DRIVE_SIGNING_SHA256` carry the same public values. Runtime requires the installed signing SHA-256 to match. Real Android package/signing SHA-1 OAuth registration, Drive API enablement, consent/test-user and final signing checks are external gates. No client secret, backend token exchange, remote AI or telemetry code was added.

Internet permission is explicit for Drive; ACCESS_NETWORK_STATE remains removed. `network_security_config.xml` denies default platform TLS via the dedicated non-public certificate `penny_network_deny_ca.crt`; only exact `www.googleapis.com` trusts system roots, and cleartext is disabled. The certificate contains only a public X.509 certificate; its generated private key went to `/dev/null`. `p5-public-deny-certificate.log` records public subject/fingerprint. The original `.pem` extension was changed to `.crt` so the public resource is not silently excluded by the repository's secret-file ignore rule.

The credential-free network probe received HTTP 401 from the Drive endpoint after successful TLS and an SSL trust failure before HTTP from `firebaselogging-pa.googleapis.com`. This proves the tested platform TLS paths only. It does **not** establish that ML Kit/AICore custom/native networking or the same allowed host cannot send operational metadata. Official ML Kit disclosure, final SDK traffic capture and accurate Data safety remain release gates; no blanket “no analytics” claim remains in Android README/UI.
