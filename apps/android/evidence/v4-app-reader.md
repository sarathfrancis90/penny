# App-linked v4 reader

The Android app now compiles the same Kotlin/JNI frame and logical codecs as the isolated prototype. The three implementations moved into `packages/offline-crypto/android/codec/` without byte changes; neither app retains a fork. Both builds use the existing authenticated sodium CMake consumer with pinned NDK28.2.13676358, CMake3.22.1, API26 and four ABIs.

The internal `V4BackupReader.decode` requires an isolated, uncommitted sink and restricts expense, finance, receipt and metadata counts/bytes to current app bounds. It owns/closes input and sink. Its result is logical admission only; exact portable backup capacity and durable candidate preparation/install remain separate. No app UI, provider, format selection, export or live vault call site is added.

App instrumentation passed four groups on API26 and API37: two exact shared encrypted layouts; all 28 frame negatives and two non-logical frame patterns; seven authenticated logical/capacity rejections; malformed-image, close/finalization/cancellation cleanup. The malformed PNG test recomputes receipt metadata and transcript, then confirms the composed rejection originates in `ReceiptImage.decode`. Every group verifies an isolated live fixture vault and its authenticated metadata remain unchanged. Borrowed receipt buffers are wiped and JNI handle counts return to zero.

Two targeted prototype smoke tests passed on API37 after compiling the moved shared sources, covering independent frame positives and native-image logical admission. App JVM25/25, build and lint passed. Current APK/source/command hashes and fixture manifests are pinned in `v4-app-reader.json`; outputs are under `artifacts/offline/v4-app-reader/`. Earlier full prototype evidence remains historical.

All four newly packaged JNI libraries have at least16KiB LOAD alignment. All20 packaged ELF files were inspected: the existing armeabi-v7a/x86 MLKit OCR libraries retain4KiB LOAD alignment; all64-bit libraries and every new JNI library are at least16KiB. APK ZIP alignment passes `zipalign -c -P16`, and the packaged `assets/LICENSE.libsodium` matches the original license bytes exactly. Existing authenticated static sodium build outputs were reused and verified by the consumer; this slice does not claim a new upstream rebuild or reproducibility across host systems.

Builds require `-PpennySodiumOutput=ABS` or `PENNY_SODIUM_OUTPUT=ABS`. App test builds additionally need `-PpennyV4TestAssets=ABS` containing `v4-frame-negatives` and `v4-logical-materialized`; missing manifests fail the tests. Only explicit fixture filenames/extensions are copied, excluding other source/build output. The normal demo remains unchanged; test/prototype processes were stopped and API26 remains available for coordination.
