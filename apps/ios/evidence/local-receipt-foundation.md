# Local receipt foundation — native validation

2026-09-13. **9/9 focused XCTest methods pass, no skips (Tests06).** The earlier Tests05 unsigned iPhoneOS Release compilation passed; the changed parent-read precondition was not separately device-rebuilt. Exact commands, source/fixture hashes, runtime and evidence hashes are in [local-receipt-foundation.json](local-receipt-foundation.json). Raw local evidence is `apps/ios/.build/local-receipt-foundation/Tests06.xcresult`, `xcodebuild06.log`, `summary06.json` and `device-build.log`. The isolated F70 iPhone 16e simulator ran iOS 26.4.1 (23E254a), arm64, and was shut down afterward.

The simulator implementation is selected at compile time and truthfully reports `simulatedFilesystem`. It uses exclusive descriptor-relative `openat`; it does not simulate or claim class A. Device builds select `openat_dprotected_np` with class A and require real descriptor protection readback on both creation and fresh reopen. Device test assertions additionally require actual-path `.complete` metadata. No runtime error can switch implementations. The device SDK build's C object references `_openat_dprotected_np`; this establishes compilation, not physical-device operation or lock-state protection.

The passing suite covers the shared CryptoKit golden, exact HMAC key/AAD, all 35 shared negatives, per-byte tamper and strict length, current native image decode, 100-receipt/8-MiB capacity, duplicate rejection, generation transfer/read and one-shot ownership. Filesystem checks include exclusive collision/symlink preservation, foreign file replacement, parent-directory substitution preserving victim bytes and attributes, UID/private modes, hardlink rejection, inode pinning and exact inventory both before and after completion reads. Enumeration explicitly rewinds because duplicated directory descriptors share the offset. Added unowned entries are rejected and preserved. Explicit cleanup errors remain visible; deinitialization is best effort.

Fault tests execute a real first 64-KiB ciphertext write before an injected partial-write failure, and inject errors after real sync/close or before reopen/completion. They prove bounded checkpoint cleanup and an unchanged sibling, not real full-volume, kernel-close or power-loss behavior. Cancellation after close is exercised. If actual `fstat` fails before ownership can be established, the foundation reports failure and leaves the unidentified entry rather than deleting a name without verified identity.

The historical direct protected-creation simulator run remains intact: `Tests03.xcresult`, `provenance03.json` and `REPORT.md` record **2 passed / 7 failed / 0 skipped** with `EPERM`. It is not overwritten or reclassified. Tests04 was the first successful compile-time simulator run; Tests05 adds final inventory and fresh-descriptor protection validation.

This is a typed descriptor and unactivated receipt-generation foundation with no live-store callers. The JSON metadata cases in the shared corpus use a test-only closed-descriptor adapter; this is not a production serialized metadata parser. Supplied device keys, random runtime nonces and native CryptoKit are used; no production libsodium dependency was introduced. Authenticated full-candidate metadata and revision/incarnation/key/provider/session bindings, live activation/rollback, durable retention, process recovery, garbage collection and capacity increases remain separate work. Physical-device protection remains mandatory before adoption.

Tests06 removes all generation-directory pathname metadata mutation. The owner provisions a private, backup-excluded parent before exposing it as a storage context; initialization checks the original parent against the pinned FD before and after reading its exclusion flag. Children inherit backup exclusion. The test provisions its own parent and rejects a private parent lacking explicit exclusion. Atomic class-A receipt creation on device is unchanged.
