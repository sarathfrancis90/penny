# Penny Offline shared contract

Data-only schemas, 38 exact existing Canadian category strings, public interoperability fixtures, and an executable Node reference for the native apps. There are no third-party runtime dependencies. This package is not a cloud service and is not linked into either native app.

Run from the repository root:

```sh
node --test packages/offline-contract/*.test.mjs
```

Native tests should decrypt `fixtures/backup-v1.pennybackup` with the **public test** key in `fixtures/golden-vector.json` and compare fields with `fixtures/snapshot-v1.json`. They should also apply `fixtures/conformance.json` mutations. JSON member order is not a wire requirement; decrypt exact ciphertext bytes before decoding.

Schema 2 adds bounded, embedded receipt bytes. Native tests also decrypt `fixtures/backup-v2.pennybackup` using `golden-vector-v2.json`, compare `snapshot-v2.json`, decode the synthetic `receipt.png`, and reject every mutation in `conformance-v2.json`. The encrypted envelope remains format 1. `snapshot.schema.json` remains the frozen v1 schema; `snapshot-v2.schema.json` describes v2. `upgradeSnapshot` validates a v1 snapshot before copying every field and changing only its schema version. Unknown or unrepresented legacy fields fail validation.

Schema 3 adds the bounded financial domains in [`FINANCE_CONTRACT.md`](../../docs/offline/FINANCE_CONTRACT.md). Its schema, complete encrypted golden, explicit monthly calculation expectations, invalid corpus and CSV sample are `snapshot-v3.schema.json`, `fixtures/backup-v3.pennybackup`, `fixtures/finance-golden.json`, `fixtures/conformance-v3.json` and `fixtures/expenses-v3.csv`. `finance.mjs` supplies deterministic validators, Gregorian recurrence, idempotent posting proposals, reports, rollover, savings progress and safe CSV. `upgradeFinanceSnapshot` validates before copying v1/v2 into v3 with empty financial arrays; the P2 `upgradeSnapshot` helper refuses to downgrade v3.

`fixtures/native-exports/` contains captured native runtime v2 and v3 archives, with SHA-256/source/runtime provenance. These are synthetic public-key test files independently decoded by the reference, not regenerated by the Node fixture generator. Both native suites should require the other platform's captured archive and fail if it is missing; no local `.build` artifact or skipped test should be needed in hosted CI. Records are compared by ID, since native storage may export arrays in a different display order.

The same directory contains `ios-cloud-v1` and `android-cloud-v1` manifest/snapshot pairs, with `cloud-provenance.json`. The shared cloud test requires both captures, verifies their exact hashes, authenticates manifest-to-snapshot binding and compares all eight schema 3 arrays. These came from native controllers using fake providers and the public cloud test key; they establish runtime crypto interoperability, not real CloudKit/Drive transfers. Native cross-reader tests can consume these stable files without another platform's local build directory.

`node packages/offline-contract/generate-fixtures.mjs` deliberately regenerates reviewed schema and fixture artifacts. Do not regenerate as a way of making a failing native crypto test pass. Category regeneration refuses an unexpected category count and tests verify exact correspondence with `packages/shared/src/categories.ts`.

`contract.mjs` uses Node's standard AES-GCM implementation and has a fixture-only deterministic nonce seam. `sealBackup` always chooses a fresh random nonce; use that entry point outside fixture generation. Native production code must always use OS random nonces and a random independent recovery key. Reference image validation checks media signatures and declared dimensions, not full decoding; native apps must fully decode within the dimension/pixel limits before committing. Reference preflight tests do not prove native disk transactions, cloud transport, or device key lifecycle.

`fixtures/png-integrity-corpus.json` adds 24 public synthetic native image-admission cases (five valid, 19 invalid) without changing the portable schema. Both native suites must preserve accepted PNG bytes and reject the invalid cases before saving/restoring. Controls include noninterlaced/Adam7 images, empty passes, one-byte IDAT splits and grayscale/indexed palettes. Faults cover row filters, scanline length, zlib checksum/completion/trailing data and the aligned chunk-name, critical-chunk, palette and animation rules; all chunk CRCs are correct. The Node fixture test verifies exact bytes and isolated stream faults, not general PNG image admission. `node packages/offline-contract/generate-png-fixtures.mjs` deliberately regenerates only this corpus.

The architecture, security boundary, recovery UX, migration, and release requirements are in [`BACKUP_CONTRACT.md`](../../docs/offline/BACKUP_CONTRACT.md).

Optional cloud backup has a distinct immutable manifest format in [`CLOUD_BACKUP.md`](../../docs/offline/CLOUD_BACKUP.md). `cloud-manifest.mjs` validates and authenticates it, derives opaque binding tags and verifies referenced portable snapshot bytes; public independent vectors are `fixtures/cloud-*-v1.*`. `cloud-publication.mjs` is a deterministic protocol model for native adapters, including account/cancellation/revision guards and verified readback. It performs no provider IO and emits no deletion; its tests are not evidence of real cloud backup or provider durability.
