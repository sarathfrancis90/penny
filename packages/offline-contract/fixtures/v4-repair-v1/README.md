# Current-cap v4 repair acceptance

`acceptance.json` specifies the next in-place repair slice. All cases remain
`required_unproven`; platform evidence, not this file, records execution.

The manifest references the existing captured native writers and expected
snapshots. Do not regenerate, copy or edit those archives. Each platform must
exercise the opposite native writer. Public fixture keys are synthetic only.

This is an explicit exception to the older candidate fixture's
`missing_device_key` rejection: ordinary candidate preparation still rejects
missing keys; a distinct source-bound repair preview may validate the external
archive. It grants no permission to provision a key or publish until explicit
Replace. Unreadable target state is preserved as evidence, never authenticated
as an empty vault. All existing parser, image, capacity and publication guards
remain in force.

A successful install compares every represented record and raw receipt with
the pinned expected snapshot. Local replacement identity follows the existing
store contract; snapshot export identity is not an additional equality rule.
No higher-capacity, provider, physical-device or crash-recovery claim follows.

After explicit Replace only, failed preparation may retain its exclusively created
owned key for a fresh user-confirmed retry, or safely remove it. This does not
authorize adopting/deleting a foreign key or creating one during preview.
