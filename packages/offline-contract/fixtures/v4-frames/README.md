# Experimental v4 frame fixtures

These public files exercise the frame layer in the draft
[`BACKUP_V4_CONTRACT.md`](../../../../docs/offline/BACKUP_V4_CONTRACT.md).
They do **not** establish complete logical archive admission, restore safety,
capacity qualification, or a frozen/production format. Existing v1–v3 fixtures
and readers are unchanged.

`fixture-manifest.json` records every plaintext/ciphertext byte count and SHA-256,
the public recovery key, source pin, and compact negative recipes.

| File | Plaintext | Frames |
| --- | --- | ---: |
| `empty-ledger.pennyframe` | 716-byte logical example from `v4-design/layout-vectors.json` | 1 |
| `one-receipt.pennyframe` | 1,410-byte logical example from the same layout | 1 |
| `full-final.pennyframe` | 1 MiB, byte at absolute offset `i` is `i % 251` | 1 |
| `multi-frame.pennyframe` | 2 MiB + 37, same absolute-offset pattern | 3 |

The first two carry logical example bytes; the frame oracle does not interpret
them. The pattern files are frame test inputs, not logical archives. The full-size
final fixture verifies that a final 1 MiB chunk has tag FINAL with no empty frame
appended. Positive ciphertext totals 3,148,369 bytes.

All keys and plaintext here are deliberately public. The root is 32 bytes of
`07`; the wrong-key recipe uses 32 bytes of `08`. Ciphertext is generated by
the pinned upstream libsodium HKDF and secretstream APIs. To permit exact
regeneration, the generator explicitly installs libsodium's documented custom
randomness hook with a deterministic **public test** byte source. This hook and
these salts/headers/keys must never be used for application encryption.

Twenty-eight malformed cases are stored as recipes and expected hashes, avoiding
repetitive multi-megabyte invalid files. They include authentication failures,
reordering, duplication, splicing, truncation, missing FINAL, forbidden authenticated
tags, noncanonical frame shapes, unsigned bounds, and strict EOF/prefix failures.
`expectedError` is an oracle diagnostic; other implementations need to reject and
discard tentative output, without matching its error vocabulary.

Build, read-only verification, and temporary negative-file materialization commands
are in [`prototypes/reference/README.md`](../../../offline-crypto/prototypes/reference/README.md).
