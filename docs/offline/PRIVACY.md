# Penny Offline privacy inventory and store-answer draft

Reviewed 2026-09-13 against native source through P6 storage, worker and artifact preparation. This is an internal preparation document, not a published privacy policy or completed store questionnaire. Manual provider adapters and default-off automatic coordination pass local native gates; real-account publication, clean-install recovery and final signed-artifact behavior remain unverified. Reconcile this inventory against the exact release binaries and their resolved dependencies.

## Data and transfer inventory

The native core works without a Penny account, network service or available generative model. Expenses, receipts, budgets, income entries, savings ledgers and reports are local. Scheduled income is not actual received cash. Optional model suggestions require review and cannot perform financial writes. The retained Flutter/API product has different data practices and is not covered by these native-only observations.

| Data | Current native handling | Off-device boundary and retention |
| --- | --- | --- |
| Expenses and finance records | Merchant, CAD amounts, civil dates, categories, description/note, budgets, income source/received entries, savings goals/contributions and recurring templates are encrypted in the local vault. Reports derive from these records. | Encrypted portable export is explicit. Dedicated encrypted provider backup is implemented, configuration-gated and opt-in. Deleting a local record does not rewrite existing exported or remote generations. |
| Receipt images | User-selected JPEG/PNG bytes are retained exactly when already admissible. Camera/HEIC/oversize preparation creates a reviewed JPEG copy. Both platforms validate images before encrypted persistence. | Existing originals may include EXIF or location metadata: do not claim all retained images strip GPS. Prepared copies omit source metadata. Images travel inside encrypted backups; the original selected file remains under its existing owner's control. |
| OCR and model data | OCR source text, locale, proposals and model responses are draft evidence in memory. Raw OCR has no persisted snapshot field; text the user saves in a note becomes a normal vault record. Vision/Foundation Models on iOS; bundled ML Kit OCR and optional Gemini Nano on Android. | No app cloud inference fallback. OS model installation/updates and SDK operational metrics are distinct from inference input/output; see the Android gate below. |
| Local encryption keys | iOS uses nonsynchronizing `WhenUnlockedThisDeviceOnly` Keychain entries. Android stores encrypted records under `noBackupFilesDir`; its Keystore key wraps a random AES-256 software data key, with versioned wrapped-key metadata committed atomically with migrated rows. Each operation authenticates and unwraps the current envelope; row batches use the software key in memory. | Local keys and wrapped-key metadata are not part of portable snapshots. Software row keys and iOS worker keys exist in app memory during use. Simulator/emulator tests do not establish physical secure-hardware properties, memory erasure or uninstall behavior. |
| Portable recovery key | Independently generated; explicit re-entry and protected storage/readback are required before confirmed export. The Android key dialog offers explicit sensitive clipboard copy with bounded clearing of owned content. | Never embed in backup/manifest, provider credential, logs or analytics. A user-kept copy has its own storage risk; losing all usable copies can make recovery impossible. Clipboard protections do not control every keyboard, OS or receiving app. |
| Export files | Encrypted backup staging is protected, excluded from automatic backup and cleaned after the operation. Fresh UUID names, no overwrite of existing nonempty destinations and authenticated readback precede success. | Files/SAF can route the user's chosen destination to another provider. Local document readback proves that interface's returned bytes, not completed remote upload. User-held copies remain until removed by the user/provider. |
| CSV | Explicit warning and user-selected export of all expense details, with formula escaping. | CSV is readable plaintext. It is neither a complete vault backup nor protected by the recovery key; the chosen destination or recipient can read it. |
| Provider identity and metadata | Selected opaque provider identity is used for account binding. Authenticated encrypted manifests contain opaque account/vault tags, writer/revision, IDs, digest, byte count and timestamps. No email, password, token or plaintext balance belongs in a manifest. | CloudKit private database / Drive `appDataFolder` receive encrypted snapshots and manifests. Providers also handle authorization and request/object metadata outside those encrypted payloads. Hashing an identifier does not establish anonymity. |
| Automatic backup state | Opt-in, provider/key/vault binding and verified status are protected locally. A nonfinancial stop marker prevents failed setting writes from reviving disabled work. iOS uses one app-owned coordinator; Android uses one process lease and unique WorkManager work. | Off by default; no new finance payload fields. OS scheduling is inexact. Disabling or pausing preserves existing remote generations. Real background provider/key behavior remains a device gate. |
| Diagnostics | No intentional Penny analytics, ads, remote crash reporter or receipt/prompt logging was found in the native core. Android dependencies have a separate documented metrics boundary. | Do not translate “no app analytics SDK configured” into “no SDK data collected.” User-submitted support files and OS/store diagnostics need their own inventory before being enabled or used. |

Source anchors: iOS `VaultStore.swift`, `PreparedVaultWrite.swift`, `ArchiveWorker.swift`, `RecoveryExport.swift`, `ReceiptPreparation.swift`, `LocalAssistant.swift`, `VaultView.swift`; Android `VaultStore.kt`, `RecoveryKeyStore.kt`, `BackupExporter.kt`, `ReceiptImage.kt`, `LocalIntelligence.kt`, `RecoveryDialog.kt`; shared schema 3 and [cloud contract](CLOUD_BACKUP.md). iOS app-support files are excluded from automatic backup. Android source disables platform backup and excludes app data from cloud backup/device transfer. Verify these settings in the final artifacts; dedicated optional backup is a separate feature. P6 moves validated iOS archive/write preparation onto a serial worker without changing which content enters a backup or enabling a new network path.

## Android SDK diagnostics gate

At review, dependencies are `com.google.mlkit:text-recognition:16.0.1` and `com.google.mlkit:genai-prompt:1.0.0-beta4`. Google's current disclosure identifies device/app information, installation identifiers, latency, API configuration, input/output sizes, feature events/errors and GenAI configured languages; GenAI can also involve user/device identifiers. These are diagnostics and usage analytics, not receipt text or image content. The page covers latest SDK versions, so compare its scope with the resolved release dependency graph. [ML Kit data disclosure](https://developers.google.com/ml-kit/android-data-disclosure).

Google states that ML Kit processes inputs and outputs on device while sending API performance/utilization metrics and occasionally contacting servers for updates. Its terms place responsibility on the app to inform users of metrics processing. Thus “on-device AI” and “no telemetry” are different claims. [ML Kit terms and privacy](https://developers.google.com/ml-kit/terms).

No documented supported **complete telemetry-disable switch** for the selected standalone APIs was found in the reviewed public documentation. The public `MlKit` entry point allows control over automatic initialization; that is not a documented metrics opt-out. The deprecated Firebase `FirebaseVision.setStatsCollectionEnabled` belongs to another API and cannot establish an opt-out for these dependencies. Do not use private reflection or internal logging switches as a release guarantee. [Standalone initialization API](https://developers.google.com/android/reference/com/google/mlkit/common/MlKit), [deprecated Firebase API](https://firebase.google.com/docs/reference/android/com/google/firebase/ml/vision/FirebaseVision).

The P5/P5b Android manifest grants Internet and network-state access for optional Drive and constrained work, alongside optional camera access. The implemented defense is platform TLS default-deny with system trust restricted to exact `www.googleapis.com`, cleartext disabled, and an explicit tested TLS rejection for a nonallowed host. That test cannot prove a custom/native networking stack, traffic to an allowed host, or a system service such as AICore is blocked. No telemetry traffic was established by this source review. Before release, observe the exact SDK/app/system-service traffic with backup off/on, cold start, OCR, model status/inference, error/retry, reconnect and background execution; record destinations and payload classifications without storing user receipts, prompts, keys or tokens. Resolve any unexplained egress and disclose actual collection. Blanket “zero analytics” and “no data collected” remain unapproved.

## Optional cloud and deletion wording

Both manual provider setup and automatic scheduling start disabled. Enabling requires a selected provider account and separately confirmed recovery key. Account change/revocation must stop pending work. Immutable encrypted payloads stay portable; restoring on a clean installation requires the saved recovery key and provider access, not old device-only metadata. The app must verify provider upload, download, digest/authentication and manifest readback before reporting a verified generation.

The iOS adapter uses a dedicated CloudKit private database with immutable CKAsset records and explicit database fetch verification. The Android adapter uses only Drive `appDataFolder`, creating new resumable uploads and verifying downloaded ciphertext. These flows are exercised with fake transports; signed real-account operations are still unverified. This is app-side encryption independent of provider account encryption settings. Provider authorization, network/request metadata, object sizes and names are not made invisible by payload encryption. No automatic deletion or mutable “latest” object is allowed by this slice; failed-publication orphans and older generations may remain. A restore replaces the active local vault only after preview and confirmation.

Do not promise that disabling backup, deleting a local expense, clearing app storage or uninstalling deletes remote snapshots or externally exported files. A verified provider-specific deletion/control path and an accurate retention explanation are required before publishing a deletion claim. Key rotation must explain that old generations still need their old key. No native Penny account creation/deletion UI is implemented; preserve the existing account-deletion and privacy routes for retained legacy users until migration/retirement is verified.

## Draft Google Play answers

Google excludes strictly local processing and qualifying end-to-end encrypted payloads from collection, provided intermediaries cannot read them and only sender/recipient hold keys. This does not exempt SDK metrics or provider metadata. Its global form covers every currently distributed version under the package; optional collection must be optional for all relevant users. [Play Data safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469).

| Question / field | Native draft | Required reconciliation |
| --- | --- | --- |
| Collect/share required data types | **Pending**, because ML Kit metadata and real-provider authorization/transport behavior are unresolved. | No blanket “No” while any relevant SDK or retained distributed version collects data. Qualify each transfer, recipient and exception. |
| Finance, images and notes | Local processing; backup payload is designed to satisfy the encrypted-payload boundary. CSV is an explicit readable export. | Verify recovery-key separation and all transfer paths. A user-chosen export does not excuse unrelated SDK collection. |
| Diagnostics / app activity / identifiers | Candidate mappings for documented ML Kit metrics, with diagnostics/analytics purposes. | Determine exact types/linkage and whether any supported user control applies; bundled models do not by themselves disable metrics. |
| Encryption in transit | Designed yes for provider HTTPS plus independently encrypted payloads. | Verify every actual collected-data path in the final artifact, including SDKs. AES-GCM backup alone is insufficient. |
| Optional / required | Dedicated cloud backup is intended to be optional; core entry and reports remain available without it. | Do not label SDK collection optional unless all affected users can actually control it. Retained versions also affect this answer. |
| Account creation / deletion | Native core creates no Penny account; provider sign-in enables backup only. | Preserve legacy account deletion and inventory all currently distributed versions before answering listing-wide questions. Do not equate revoking Drive consent with deleting backup objects. |

The public policy must identify the responsible publisher and contact, describe native/legacy practices, actual SDK/provider processing, retention/deletion and user choices. Check the existing `/privacy` and `/privacy/data-processors` routes and retained deletion endpoint before changing claims. [Google Play User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311).

## Permissions, required-reason APIs and final evidence

Current native capture requests camera permission only when used. iOS has a camera-purpose string; neither inspected core requests microphone or location access, broad contacts access or photo-library writes. Android camera hardware is optional. System photo/document selection and user exports still grant access to the chosen content. Inspect merged/compiled permissions in the final P6 artifacts; source permission names alone are not a complete SDK inventory.

P6 includes `apps/ios/PennyOffline/PrivacyInfo.xcprivacy` with file-timestamp reasons `C617.1` for app-container files and `3B52.1` for explicitly selected Files documents. `StrictJSON.boundedRead` uses `fstat` on the opened descriptor to bound reads and reject nonregular files. The inspected unsigned device-build audit at `apps/ios/.build/p6-privacy-build-audit.json` records the bundled manifest, direct `_fstat` import, native icon, all iPad orientations and absent debug-harness strings. This is a build inventory; it neither declares no collection nor replaces the final signed archive privacy report and linked-code inventory. No direct `UserDefaults`, boot-time or free-disk-space query was found in the inspected native core; dependencies and future code still require inspection. [Approved API categories/reasons](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype), [manifest requirement](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api).

Android P6 targets/compiles API 37, retains minSdk 26 and stable Material3 1.4.0, and has local API 26 and Android 17/16 KiB emulator evidence. Below API 28, HEIC preparation explicitly requests JPEG/PNG input; it does not upload the image for conversion. Both native ports now reject the shared malformed PNG corpus before storage or conversion, preserving valid original bytes. These checks do not establish physical minimum-API hardware, every bundled ABI or actual SDK/AICore traffic. Release evidence must include the resolved SDK inventory, final iOS privacy report/manifests, Android merged permissions and network policy, release-binary network observation, real account-switch/revocation/clean-install recovery, signed migration/upgrade, supported physical device/model results, and matching public policy/store drafts. Results in [REVIEW.md](REVIEW.md) close bounded source and local native regression gates only. [RELEASE.md](RELEASE.md) tracks the remaining sequence; no public submission or privacy-label update was performed here.
